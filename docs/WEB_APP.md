# Study Planner 正式网页版

入口：[打开学习日历](https://caiwu557-ai.github.io/study-planner/web/)。无需下载、注册、部署或开启本地服务。宣传页及其演示仍在网站首页，使用独立的虚构数据。

## 第一次使用

1. 打开链接，首次进入会出现新手指引，并插入当前一周的虚构示例课程与练习任务。指引依次切换页面、展开主题编辑、课程弹窗、任务编辑、回收站和添加事项弹窗，不会自动保存、删除或发送 AI 请求。可随时暂停，自己练习；设置中的「新手操作指引」可以重新打开。
2. 在「设置 → 载入课表」下载 Skill，把 Skill 和课表交给 AI 转换成 JSON；选择文件、检查预览，再载入。首次载入只替换标记为示例的课程、关联复习和示例任务，保留自己添加的记录；之后导入只新增并去重。编辑过的示例仍是示例，会被替换，重要修改请先导出备份。也可在周课表手动添加课程。
3. 填写课程主题后生成真实复习链；待办、到期、编辑、回收站和短时撤销均可直接使用。
4. 在「设置 → 你的浏览器存档」点击「保护浏览器存档」。浏览器是否批准取决于自身策略；即使批准，仍需导出备份。

已有浏览器存档不会插入示例，也不会自动弹出指引；重新打开指引不会重新插入示例。进度保存在当前浏览器中。

核心界面、主题、阅读设置和快捷键复用本地版；具体规则见[使用指南](USER_GUIDE.md)。时间基准为北京时间，暂不按设备所在地切换。未安排日期的任务在网页版的「仅今日」和「全部事项」均可管理，避免刚添加就找不到。

## 安装为 Web App

在支持的 Chrome／Edge 中，点击设置里的「安装应用」，或使用浏览器菜单中的「安装应用／添加到主屏幕」。安装后会出现桌面或主屏幕图标，用独立窗口打开，数据仍属于对应浏览器。

Android（包括 OPPO）建议通过 Chrome 或支持 PWA 的浏览器打开；不同浏览器的菜单名称和安装能力可能不同。iPhone 使用 Safari 的分享菜单 → 添加到主屏幕。它是浏览器支持的应用，不是本项目单独发行的 APK，也不要求用户下载安装包。

首次联网加载成功并完成缓存后，课表、复习、清单、设置和备份可离线使用。AI 和查看远程链接仍需联网。关闭浏览器、锁屏后准时提醒无法保证；不要把它作为唯一的关键截止提醒。

应用更新就绪时，设置会出现「更新已就绪 · 刷新应用」。先提交当前表单再刷新；更新仅替换应用代码，已保存的数据继续保留。不会自动刷新打断输入。

## 存档与备份

个人记录使用 IndexedDB，侧边栏状态和提醒去重使用独立的 LocalStorage 键；与演示页隔离。GitHub Pages 只提供静态应用代码，不接收个人存档。同一设备、同一浏览器配置、同一网站来源共享数据；没有账号，也不自动在电脑和手机之间同步。

- 关闭页面或重新打开链接，已保存记录继续存在。
- 无痕模式、清除网站数据、重置浏览器或卸载时清除关联数据，可能删除存档。
- 换浏览器、设备或网站域名，原数据不会自动出现。先导出备份，再到新环境恢复。
- 定期「导出备份」。它包含课程、复习、任务、回收站和设置，**不含 API Key**；备份本身没有加密，应妥善保存。
- 恢复前会校验文件并显示条数。确认恢复后替换当前记录；现有密钥及与其绑定的 API 地址、模型配置保留，其他设置按备份恢复。
- 导入课表或恢复备份前自动保留最近三份快照。可通过「导出操作前快照」取得最近一次操作前的记录，再选择该文件恢复。它仍在浏览器中，不能替代外部备份。
- 无效课表或备份整次拒绝，事务写入失败不会报告保存成功。两个标签页的写入会使用最新记录，但正在打开的界面可能需要刷新才能看见其他标签页的改动。

网页版 JSON 备份与本地版 SQLite 数据库不同，当前不能直接互相恢复。两版使用同一种课表导入文件；不要拖入数据库或秘密文件。

## API 与一句话解析

在设置填写 HTTPS Base URL、模型名称和自己的 API Key，保存后自动发送短消息测试。也可以不保存，直接测试输入的配置。

密钥单独保存在当前浏览器，不进入公开仓库或普通备份；应用没有内置公共密钥。浏览器存储不等于加密保险箱，同来源代码及有权限的扩展可能访问它，共享设备请勿保存。清除 Key 会删除本应用保存的密钥。

AI 解析会向你填写的服务商发送输入文本、可选课程名称与认证密钥，测试只发送一条短消息。没有经过本站代理的请求。服务商必须支持浏览器 CORS；网络、权限、额度或接口不兼容时会显示失败原因，仍可手动录入。更换地址时必须重新填写密钥或先清除旧密钥；重定向不跟随，防止密钥转发到其他地址。

AI 结果经过日期、字段和长度校验，分步骤、材料、注意事项、待确认整理到备注；用户确认添加后才写入任务。

## 维护与本地部署

本地部署版保留原来的 `server.py`、`static/`、`data/seed_schedule.json`、`start.bat` 和 `start.sh`；个人数据库、密钥和备份不会上传。

网页构建：运行 `python demo/build.py site` 和 `python web/build.py site`，输出静态宣传页、演示与 `/web/` 正式应用。GitHub Actions 自动构建、检查浏览器算法、发布到 Pages。最终用户不需要执行这些步骤。

网页版在 `web/` 下实现浏览器存储与 Python 后台规则的对应逻辑，构建时复用 `static/` 的界面文件。以后修改复习或导入规则，需要同步两端并运行后端测试、`tests/web_engine.mjs` 和 `tests/web_ui.cjs`。图标为本项目绘制；设计参考温暖纸面、清晰字号与克制强调色，没有引用 Notion 的专有字体或素材。
